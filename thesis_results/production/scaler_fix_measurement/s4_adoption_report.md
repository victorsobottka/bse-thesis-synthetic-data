## 3. The scaler leak

`compute_discriminative_score` now builds `Pipeline([StandardScaler(), LogisticRegression(max_iter=300, random_state=42)])` and hands the raw stacked features to `cross_val_score`, so the scaler is fitted inside each training fold, on the contiguous and the purged path alike. Fold construction is unchanged. All three callers (the null, the Track A metric, the walk-forward call) go through it. Tests: the previous notebook equals a hand-written global-scaling version exactly (max |difference| 0); the new one equals a hand-written per-fold-scaling version exactly (0), on 50 real adjacent-block pairs × both schemes.

**Consequence in the code, not regenerated:** `precompute_auc_null` caches `auc_null.json` under a key of B, seed, window, n_splits, n_real and the series hash, none of which changes with the fix, so the existing (leaky) caches would have been reused against post-fix AUCs without warning. The key now carries `auc_scaler: fit_within_training_fold`; the five existing files lack it, so the next pipeline or Phase B run treats them as stale and recomputes them. I did not regenerate them.

**Published AUC values are not overwritten**, and are flagged with the column `discriminative_auc_pre_scaler_fix = True` in every metrics file and `overall_summary.csv`. Which published values can be recomputed after the fix (`published_subset_auc.csv`, pre-fix value against the published `discriminative_auc_raw`): 
GARCH 0.0e+00, control 5.6e-17 (bit level); GJR-GARCH 2.2e-05 (the saved series is float32); TimeGAN 7.5e-04 through the CPU-RNG replay of the first `generate()` call (the replayed series differs from the stored second draw by up to 5.4e-04, CPU against the GPU arithmetic of the original). QuantGAN and CNN-WGAN-GP cannot be recomputed (CUDA RNG state never saved). So a consistent post-fix column for all five models cannot exist. Post-fix values are in separate files: `scaler_fix_measurement/published_subset_auc.csv` (four series per unit), `observed_frameF_auc.csv` (fresh draws, all five models and the control), `nulls/*_fixed.npy` (post-fix sliding nulls), `legacy_999_null_pre_post.json`. Under S4 none of this touches the composite.

### Does any audit conclusion change?

**No.** (1) *No cell clears a calibrated threshold:* in Frame F, 0 of 25 above p97.5 and 0 of 25 above mean + 1.96 sd under all four combinations of scheme and scaler. One qualification I should have carried before: on the **published** draw one cell, FTSE / TimeGAN (0.832 against a p97.5 of 0.805), is above p97.5 (not above mean + 1.96 sd) — the same before and after the fix, so the fix does not create it, but the statement "zero of 25" is exact for the fresh-draw cells and for mean + 1.96 sd, and 1 of 25 for published values at p97.5. (2) *The null sits well above 0.5 on real data:* Track A null means after the fix are 0.567–0.693 (contiguous) and 0.551–0.675 (purged), walk-forward 0.522–0.663; before, 0.571–0.693, 0.556–0.675 and 0.525–0.663. (3) *The control's AUC is set by drift direction:* 0.320–0.702 (contiguous) and 0.309–0.680 (purged) after, 0.320–0.701 and 0.310–0.677 before; the ordering across markets is the same. (4) *Purged CV does not repair the metric:* NIFTY50's anti-predictive draws stay at 0.375 → 0.352 post-fix (0.380 → 0.358 before). The leak was real and is fixed; it did not carry any of these conclusions.
